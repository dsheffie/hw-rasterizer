Depth in the hardware rasterizer

How per-fragment depth is set up on the host and interpolated in the RTL.

This rasterizer follows the SGI CRIME model (CRIME 1.5 spec, §7.3.5–7.3.7): the host computes the triangle's plane equation, and the hardware contains only steppers — adder/subtractors that walk the value across the bounding box one pixel at a time. Nothing is divided or multiplied per pixel; the host hands the RTL a starting value plus per-step increments, and the RTL reaches every pixel with adds and subtracts.

The same machinery does two independent jobs: coverage (is this pixel inside the triangle?) via three edge functions, and depth (what is z here?) via the depth plane equation. The host side of both lives in setup.cc; the stepping lives in rasterize.sv.

The host side: setup_triangle()

setup.cc

setup_triangle() takes three (x,y,z) vertices and returns the values the RTL needs at the pixel where it starts scanning.

1. The start corner

int32_t xs = std::min(std::min(v0.x, v1.x), v2.x);
int32_t ys = std::min(std::min(v0.y, v1.y), v2.y);

(xs, ys) is the upper-left corner of the triangle's bounding box — exactly where the RTL begins (COMPUTE_BB sets r_x = x_min, r_y = y_min). Every initial value below is therefore computed at the precise pixel the hardware steps away from.

2. Edge functions (coverage)

// (b-a) x (p-b)  -- the edge function for directed edge a->b at point p
int32_t cross(const vertex2d &a, const vertex2d &b, const vertex2d &p);

s.w0 = cross(v0, v1, p);   // edge v0 -> v1
s.w1 = cross(v2, v0, p);   // edge v2 -> v0
s.w2 = cross(v1, v2, p);   // edge v1 -> v2

Each edge function is a signed quantity: zero on the edge's line, positive on one side, negative on the other. A pixel is inside the triangle when all three share a sign — in this design, all ≥ 0. The RTL's coverage test is exactly (r_w0[31] | r_w1[31] | r_w2[31]) == 0 (no sign bit set). setup.cc computes only the starting weights; the RTL steps each one by that edge's dx/dy (derived on-chip from the vertices) as it scans.

The edge ordering (v0→v1, v2→v0, v1→v2) is a contract with the RTL: it must match how the hardware pairs each weight with its edge deltas. Change the stepper wiring and these three lines have to change with it.

3. The depth plane

The plane z(x,y) = A·x + B·y + C through the three (x,y,z) vertices is solved by Cramer's rule. The shared denominator is twice the signed triangle area; the gradient numerators are the determinants with the z-column swapped in:

int64_t area     = x0*(y1-y2) - y0*(x1-x2) + (x1*y2 - x2*y1);  // 2 * signed area
int64_t dzdx_num = z0*(y1-y2) - y0*(z1-z2) + (z1*y2 - z2*y1);  // = area * dz/dx
int64_t dzdy_num = x0*(z1-z2) - z0*(x1-x2) + (x1*z2 - x2*z1);  // = area * dz/dy

4. Normalize once, into fixed-point

The real gradients dz/dx, dz/dy are fractional (e.g. 0.8), so plain integers would round them to 0 and depth would be flat. Instead we divide by area once per triangle and keep the result in signed fixed-point with DEPTH_FRAC_BITS fraction bits:

s.dzdx = (dzdx_num << DEPTH_FRAC_BITS) / area;   // true dz/dx, Q.DEPTH_FRAC_BITS
s.dzdy = (dzdy_num << DEPTH_FRAC_BITS) / area;

int64_t z0_fx = (int64_t)v0.z << DEPTH_FRAC_BITS;
s.z_start = z0_fx + s.dzdx*(xs-v0.x) + s.dzdy*(ys-v0.y)
          + (1 << (DEPTH_FRAC_BITS-1));            // +0.5 LSB: round, not truncate

z_start is the depth at the start corner (CRIME EQ 10, scaled), and the half-LSB makes the RTL's later fraction truncation behave as round-to-nearest.

The fixed-point format

The format is a single source of truth, declared as named constants on both sides of the hardware/software boundary — they must match.

ConstantValueMeaning
DEPTH_FRAC_BITS12fraction bits carried by the stepper
DEPTH_INT_BITS25integer bits (24-bit depth + sign headroom)
DEPTH_W37total stepper width = 25.12, CRIME's depth format

DEPTH_FRAC_BITS is defined in both setup.h (host) and rasterize.sv (RTL).

Why this matters: a fixed width is independent of triangle/screen size (the older z·area scheme grew without bound), and because every triangle's depth is normalized to the same units, depth values are directly comparable across triangles — a hardware depth test would be a plain < comparator with no per-fragment divide.

The hardware side: the depth stepper

rasterize.sv

The RTL loads z_start and steps it — nothing more:

// load at the start corner
n_z = z_start;  n_z_y = z_start;

// advance one pixel in +x
n_z = r_z + dzdx;

// wrap to the next row (x resets, y advances)
n_z = r_z_y + dzdy;  n_z_y = r_z_y + dzdy;

// emit the fragment depth: drop the fraction bits (truncate to integer)
r_pixelq[...] <= 32'(r_z[DEPTH_W-1:DEPTH_FRAC_BITS]);

r_z tracks the current pixel's depth; r_z_y latches the row's starting depth so each new row resumes from the correct value. Because the depth is already normalized, the emitted pixel_q is true depth — no further scaling needed downstream.

The software z-buffer in top.cc keeps a per-pixel nearest depth and writes a fragment's color only if it passes the test. Because depths are comparable across triangles, two triangles whose planes intersect produce a clean depth seam — the regression scene draws exactly that.

The trade-off

  • Gained: bounded register width; one divide per triangle instead of per fragment; cross-triangle-comparable depths (no normalization before the depth test).
  • Cost: a small, bounded rounding error in the gradients (held to the low fraction bits). Near a seam where two planes have nearly equal depth, integer-rounded ties resolve to the first-drawn triangle — correct behavior for a LESS depth test.

This is the standard hardware choice: bounded width with tiny rounding beats exact but unbounded width, because bounded width and comparable depths are what let depth be pipelined in silicon.
