The hardware rasterizer: from OBJ to pixels

End-to-end pipeline: a 3D model on disk becomes a shaded, depth-buffered image.

This project follows the SGI CRIME model (CRIME 1.5 spec, §7.3.5–7.3.7): the hardware (RTL) accelerates only 2D screen-space rasterization; everything before that — transforms, projection, culling, lighting, plane-equation setup — is done on the host. So rendering a 3D model is really a host-side software front-end feeding screen-space triangles to a small, fast rasterizer.

Architecture at a glance

bigguy.obj ↓ obj.cc load + triangulate → model-space triangles ↓ pipeline.cc transform / project / cull / shade → screen-space triangles (x,y,z) + color ↓ setup.cc edge functions + depth plane (fixed-point) → RTL inputs ↓ rasterize.sv step coverage + depth across the bounding box → fragments (addr, depth) ↓ top.cc software depth test + framebuffer → raster2d.ppm

1. Loading the model

obj.cc

A minimal Wavefront OBJ reader: v lines give vertex positions, f lines give faces. Only the vertex index of each f token is used (the v/vt/vn texture and normal indices are ignored — normals are computed from geometry later). Polygons are fan-triangulated (an n-gon becomes n−2 triangles), so the quad meshes here come out as triangles. The result is a list of model-space triangles.

2. The 3D software pipeline

pipeline.cc

project_mesh() turns model-space triangles into the screen-space triangles the rasterizer consumes. The transform math is done in float; only the final pixel coordinates and depth are quantized to integers, keeping the RTL integer-only.

Auto-fit, then model / view / projection

The model is centered on its bounding-box centroid and uniformly scaled to roughly [-1,1], so any model lands in view regardless of its native units:

model = rotateY(35°) * scale(2/extent) * translate(-center);
MV    = translate(0,0,-4) * model;          // camera 4 units back, looking -z
P     = perspective(fovy=50°, aspect, near=0.1, far=100);

Reject, project, viewport

For each triangle, vertices go to eye space via MV. Triangles touching the near plane are rejected (first-cut clipping; keeps the perspective divide well-behaved). Survivors are projected and divided by w to NDC, then mapped to the screen and to a quantized depth:

if (eye.z > -near) reject;                  // at/behind the near plane

ndc   = clip.xyz / clip.w;                   // perspective divide
sx    = (ndc.x*0.5 + 0.5) * width;
sy    = (0.5 - ndc.y*0.5) * height;          // flip y: screen origin is upper-left
depth = (ndc.z*0.5 + 0.5) * 65535;           // window depth, 16-bit
Why this works with affine depth. The rasterizer interpolates depth linearly in screen space. That is exactly correct for projected geometry: window depth is a plane in screen space. (Perspective non-linearity only affects attributes like color/texture, which aren't interpolated here.) So the entire 3D upgrade is new host code — the rasterizer and the depth path are unchanged.

Winding fixup and flat shading

The RTL's coverage test assumes one winding (all edge weights ≥ 0, i.e. positive screen area). After projection a front-facing triangle may come out either way, so each triangle's screen area is checked and its last two vertices swapped if needed (degenerate, zero-area triangles are dropped). Visibility is left to the depth buffer — back faces still rasterize but lose the depth test — so no explicit backface cull is needed in this first cut.

Shading is flat per triangle from the eye-space face normal and a directional light, made two-sided so the camera-facing surface is always lit:

N  = cross(e1-e0, e2-e0);  if (N faces away) N = -N;   // two-sided
k  = ambient + (1-ambient) * max(0, dot(normalize(N), L));
rgb = base * k;

3. Per-triangle setup

setup.cc

Given one screen-space triangle, setup_triangle() computes the values the RTL needs at the pixel where it starts scanning (the upper-left corner of the bounding box), so the hardware only has to add and subtract from there. It does two independent jobs: coverage and depth.

Edge functions (coverage)

// (b-a) x (p-b): the edge function for directed edge a->b at point p
s.w0 = cross(v0, v1, p);   // edge v0 -> v1
s.w1 = cross(v2, v0, p);   // edge v2 -> v0
s.w2 = cross(v1, v2, p);   // edge v1 -> v2

Each is zero on the edge's line, positive on one side. A pixel is inside when all three are ≥ 0; the RTL's test is (r_w0[31] | r_w1[31] | r_w2[31]) == 0. Setup computes the starting weights; the RTL steps them.

The depth plane

The plane z(x,y) = A·x + B·y + C through the three vertices is solved by Cramer's rule; area is twice the signed triangle area, the numerators are the gradients scaled by area:

int64_t area     = x0*(y1-y2) - y0*(x1-x2) + (x1*y2 - x2*y1);  // 2 * signed area
int64_t dzdx_num = z0*(y1-y2) - y0*(z1-z2) + (z1*y2 - z2*y1);  // = area * dz/dx
int64_t dzdy_num = x0*(z1-z2) - z0*(x1-x2) + (x1*z2 - x2*z1);  // = area * dz/dy

Normalize once, into fixed-point

The real gradients are fractional, so plain integers would round them to 0. Instead we divide by area once per triangle into signed fixed-point with DEPTH_FRAC_BITS fraction bits:

s.dzdx = (dzdx_num << DEPTH_FRAC_BITS) / area;   // true dz/dx, Q.DEPTH_FRAC_BITS
s.dzdy = (dzdy_num << DEPTH_FRAC_BITS) / area;

int64_t z0_fx = (int64_t)v0.z << DEPTH_FRAC_BITS;
s.z_start = z0_fx + s.dzdx*(xs-v0.x) + s.dzdy*(ys-v0.y)
          + (1 << (DEPTH_FRAC_BITS-1));            // +0.5 LSB: round, not truncate

The fixed-point format

Declared as named constants on both sides of the hardware/software boundary — they must match.

ConstantValueMeaning
DEPTH_FRAC_BITS12fraction bits carried by the stepper
DEPTH_INT_BITS25integer bits
DEPTH_W37total stepper width = 25.12, CRIME's depth format

DEPTH_FRAC_BITS is defined in both setup.h (host) and rasterize.sv (RTL).

Normalizing once per triangle gives a fixed stepper width (independent of triangle/screen size) and depths that are directly comparable across triangles — so the depth test is a plain < comparison with no per-fragment divide.

4. The hardware: coverage + depth steppers

rasterize.sv

The RTL walks the triangle's bounding box one pixel at a time. At each pixel it holds the three edge weights and the depth; moving in +x or wrapping to the next row is just an add/subtract:

// load at the start corner
n_z = z_start;  n_z_y = z_start;

// advance one pixel in +x
n_z = r_z + dzdx;

// wrap to the next row (x resets, y advances)
n_z = r_z_y + dzdy;  n_z_y = r_z_y + dzdy;

// a fragment is emitted only where all three edge weights are >= 0;
// its depth drops the fraction bits (truncate to integer)
r_pixelq[...] <= 32'(r_z[DEPTH_W-1:DEPTH_FRAC_BITS]);

Because depth is already normalized, pixel_q is true depth — no scaling downstream.

5. The software depth buffer

top.cc

The harness drives one triangle at a time (the state machine returns to IDLE between triangles), drains the emitted fragments, and keeps a per-pixel nearest depth. A fragment's color is written only if it passes the depth test; an address guard protects against any off-screen fragment:

if (addr < width*height && pixel_q < zbuf[addr]) {   // LESS: nearest wins
  zbuf[addr] = pixel_q;
  framebuffer[addr] = color;
}

Because depths are comparable across triangles, overlapping geometry resolves correctly — the nearest surface at each pixel wins, which for a closed model is its front face.

Design notes & first-cut scope

  • Affine depth is exact for projected geometry; attributes (color/texture) are not, and aren't interpolated yet.
  • Fixed-point depth: bounded width + cross-triangle-comparable depths, at the cost of a small bounded rounding error near coincident-depth seams.
  • Near plane: triangles crossing it are rejected, not clipped — fine for a model placed fully in front of the camera.
  • No backface cull: the depth buffer resolves visibility; back faces rasterize but lose the test. (Adding a cull would roughly halve rasterization work.)
  • On-screen: auto-fit keeps models in frame; a framebuffer-bounds guard is the backstop. There is no screen-edge clipping yet.
